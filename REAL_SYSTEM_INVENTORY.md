# Phoenix AI - Real System Inventory (Zero-Trust)

This inventory was generated by static analysis and runtime verification of the repository contents. It ignores all previous declarations and documents the exact files, APIs, databases, frontends, agents, and infrastructure present in the workspace.

---

## Workspace Structure

The workspace contains three distinct software systems:
1. **Phoenix AI Core Platform**: The primary AI coding assistant application.
2. **Task Manager**: A standalone, Dockerized FastAPI microservice with SQLite database storage.
3. **Phoenix Tasks**: A multi-container project containing a FastAPI Python backend and a React/TypeScript frontend with TailwindCSS.

---

## 1. Phoenix AI Core Platform

### A. Backend Services (`ai_project/api`)
* **`main.py`**: The entry point. Initializes all subsystems (tokenizer, model, RAG, sandbox, agents) and hosts 28 routes. Uses a FastAPI router and lifecycle-based async context manager `lifespan`.
* **`auth.py`**: Handles JWT verification (HS256) and Role-Based Access Control (RBAC). Implements standard password hashing with PBKDF2-SHA256 with 100,000 iterations.
* **`middleware.py`**: Contains `SecurityHeadersMiddleware`, `CSRFMiddleware` (Double Submit Cookie validation), `AuditLogMiddleware` (Structured JSON request logs), and SSRF validation function `validate_url_ssrf`.
* **`monitoring.py`**: Formulates metric logs and hosts performance metrics for request rates, latencies, tokens, and generation sessions.
* **`config.py`**: Stores environment and network CORS details (`CORS_ORIGINS`).
* **`ai_data.json`**: Flat-file JSON database storing AI model categorizations and developer metadata.

### B. Agents & Execution Sandbox (`ai_project/agents`)
* **`agent.py`**: Main reasoning agent coordinating interaction logs, memory stores, and sandboxes.
* **`orchestrator.py`**: Multi-agent coordinator delegating sub-tasks and aggregating agent actions.
* **`debugger.py`**: Automated code analyzer scanning the workspace and applying code repairs.
* **`refactor.py`**: Code refactoring specialist optimizing and documenting Python code files.
* **`sandbox.py`**: Secure runtime sandbox. Executes code in isolated Docker containers with CPU/memory limits, read-only FS, and disabled networking. Falls back to a subprocess runner if Docker is unavailable.

### C. Memory & RAG Pipeline (`ai_project/memory`)
* **`vector_db.py`**: Custom vector store. Normalizes 512-dimension model token embeddings, computes Cosine Similarity, manages an entity Graph RAG network, and performs database compaction (consolidation & expiration).
* **`rag.py`**: Document parsing and chunking engine extracting text for vector indexing.
* **`vector_migration.py`**: Utility to automate vector index migrations.
* **`memory_db.json`**: Flat-file storage representing both the vector array database and Graph relations.

### D. Inference Engine & Model Architecture (`ai_project/inference` & `ai_project/models`)
* **`model.py`**: Custom transformer architecture (PhoenixTransformer, 54M parameters). Includes weight quantization logic and LoRA adapters.
* **`engine.py`**: KV-caching inference engine handling greedy generation and token streaming (SSE).
* **`tokenizer_trainer.py`**: Custom subword tokenizer trainer and vocabulary builder.

### E. Frontend Dashboard (`ai_project/dashboard`)
* **`src/App.jsx`**: Main application state and layout manager.
* **`src/index.css`**: Pure CSS file specifying HSL color themes, glassmorphism, responsive grids, and animations.
* **`src/components/Sidebar.jsx`**: Sidebar navigation and status monitor.
* **`src/components/MessageRenderer.jsx`**: Markdown parser with syntax highlighting.
* **`src/pages/`**:
  * `ChatPage.jsx`: Dialogue container with streaming controls.
  * `SandboxPage.jsx`: Interactive code editor and console output terminal.
  * `MemoryPage.jsx`: Interface for RAG search, document uploads, and vector deletion.
  * `DebuggerPage.jsx`: Workspace scanning interface and automatic code repair list.
  * `RefactorPage.jsx`: Code refactoring tool with side-by-side diff.
  * `AIExplorerPage.jsx`: Catalog listing AI category cards and forms.
* **`src/hooks/`**: Custom React state hooks (`useChat`, `useSandbox`, `useMemory`, `useDebugger`, `useRefactor`, `useHealth`, `useToast`).
* **`src/services/api.js`**: Axios-free fetch layer appending JWT bearer authorization.

## 2. Task Manager Microservice (`task_manager`)

* **`app/main.py`**: API router exposing tasks CRUD endpoints.
* **`app/auth.py`**: JWT token creation and verification for Task Manager access.
* **`app/database.py`**: Database setup utilizing SQLAlchemy pointing to `sqlite:///./tasks.db`.
* **`app/models.py`**: Database model definition for User and Task tables.
* **`app/schemas.py`**: Pydantic validation schemas.
* **`app/crud.py`**: Database write/read functions.
* **`Dockerfile`**: Python 3.9 base image, requirements installation, and uvicorn startup.
* **`docker-compose.yml`**: Compose config building task manager on port `8001`.

## 3. Phoenix Tasks Application (`phoenix_tasks`)

### A. Python Backend (`phoenix_tasks/backend`)
* **`app/main.py`**: FastAPI router serving tasks and projects API.
* **`app/database.py`**: SQLAlchemy configuration for backend persistence.
* **`app/models.py`**: Database tables defining relationships between Users, Projects, and Tasks.
* **`app/schemas.py`**: Input/output data validator schemas.
* **`app/auth.py`**: Separate JWT authentication implementation.
* **`app/crud.py`**: CRUD logic executing SQLAlchemy database changes.

### B. React/TypeScript Frontend (`phoenix_tasks/frontend`)
* **`package.json`**: Vite frontend package defining typescript, react, and tailwindcss dependencies.
* **`src/`**: TypeScript application modules.
* **`tailwind.config.js`**: Tailwind CSS theme styling configuration.
* **`Dockerfile`**: Multi-stage build compiling static files and serving via Nginx.

## 4. Infrastructure & DevOps Files

* **`docker-compose.yml`**: Top-level orchestration composition file spinning up `backend` (port `8000`) and `frontend` (port `80`).
* **`nginx.conf`**: Top-level Nginx configuration mapping `/api` requests to `http://backend:8000` and serving frontend files.
* **`backup_restore.sh` / `backup_restore.ps1`**: Cross-platform automation scripts handling backups, gzip compression, and file restoration.
* **`run_phoenix.bat`**: Startup script activating the virtual environment and booting developers' web interface.
* **`.github/workflows/ci.yml`**: CI verification executing flake8 linters, python unit tests for all 3 applications, React compiling tests, and backend/frontend Docker building dry runs.
