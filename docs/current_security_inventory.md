# Phoenix AI - جرد المنظومة والتدابير الأمنية الحالية (Current Security Inventory)

يوثق هذا المستند التدابير والضمانات الأمنية المفعلة حالياً في خادم وتطبيق **Phoenix AI** لحماية المنصة من التهديدات السيبرانية وهجمات إساءة استخدام الذكاء الاصطناعي.

---

## 1. مصادقة الهوية والتحكم بالصلاحيات (Authentication & RBAC)

* **المسار**: `ai_project/api/auth.py`
* **التقنية**: رموز JWT (JSON Web Tokens) الموقعة بخوارزمية التوقيع المتماثل الموحد **HS256**.
* **مستويات الوصول الهرمية (Role Hierarchy)**:
  * `admin` (القيمة: 4): الصلاحية المطلقة لإدارة النظام.
  * `developer` (القيمة: 3): تشغيل الكود وفحص وإصلاح ملفات الكود.
  * `operator` (القيمة: 2): رفع مستندات RAG وتحديث مستكشف نماذج الذكاء الاصطناعي.
  * `user` (القيمة: 1): الاستخدام الطبيعي للمحادثة والبحث الدلالي.
* **آلية الحماية**: يقوم الخادم بفحص ترويسة الطلب `Authorization: Bearer <Token>` والتحقق من هوية وصلاحية المستخدم وصلاحية الرمز الزمنية قبل تمرير الطلب للمسارات المحمية.
* **حفظ كلمات السر**: استخدام خوارزمية **PBKDF2-SHA256** مع UUID Salt فريد لكل مستخدم و `100,000` دورة تشفيرية لمنع هجمات التخمين.

## 2. حزمة البرمجيات الوسيطة الأمنية (Security Middleware Stack)

يحتوي الخادم في الملف `ai_project/api/middleware.py` على ثلاث برمجيات وسيطة أمنية أساسية مرتبة بشكل متتالي:

### أ. برمجية الترويسات الأمنية (`SecurityHeadersMiddleware`)
تقوم بحقن ترويسات الحماية القياسية في كافة الاستجابات:
1. **CSP (Content Security Policy)**: منع تحميل أكواد عشوائية وحصر الاتصال بمصدر الخادم نفسه (`self`).
2. **X-Content-Type-Options**: تعيين القيمة `nosniff` لمنع المتصفحات من تخمين نوع الملفات وتفادي هجمات حقن النصوص الخبيثة كـ Javascript.
3. **X-Frame-Options**: تعيين القيمة `DENY` لمنع تضمين المنصة داخل إطارات (Frames) في مواقع أخرى وتفادي هجمات الخطف النقري (Clickjacking).
4. **Referrer-Policy**: ضبطها على `strict-origin-when-cross-origin` لتفادي تسريب البيانات في الترويسات عند الانتقال لمواقع خارجية.
5. **HSTS (Strict-Transport-Security)**: تفعيل التشفير الإجباري لنقل البيانات عبر HTTPS لمدة عام كامل عند تشغيل المنصة في بيئة الإنتاج.
6. **إخفاء هوية الخادم**: استبدال اسم الخادم الأساسي في ترويسة الاستجابة بـ `Server: Phoenix-AI` لحجب تفاصيل خادم Uvicorn عن المهاجمين.

### ب. برمجية حماية تزوير الطلبات (`CSRFMiddleware`)
* تحمي العمليات التي تغير حالة النظام (POST, PUT, DELETE) من هجمات تزوير الطلبات عبر مواقع أخرى (Cross-Site Request Forgery).
* **شروط الحصانة والاستثناء**:
  * الطلبات المرسلة باستخدام ترويسة المصادقة المباشرة `Bearer token` معفاة (لأن المتصفح لا يرسلها تلقائياً مع طلبات النماذج العادية).
  * الطلبات المرسلة بنوع محتوى `application/json` معفاة (لأن المتصفحات تعوق إرسال هذا النوع عبر النماذج العادية دون إذن مسبق CORS).
  * بالنسبة لطلبات البيانات العادية، يتم فرض فحص وجود الرمز ومطابقته في ترويسة `X-CSRF-Token`.

### ج. برمجية تدقيق السجلات والتتبع (`AuditLogMiddleware`)
* تلتقط كود الطلب الفريد `X-Request-ID` وتقوم بتسجيل تفاصيل العمليات الحساسة في السجلات بصيغة JSON منظمة.
* تسجل السجلات: المعرف الفريد للطلب، طريقة الطلب، مسار نقطة الوصول، رمز الحالة الناتج (Status Code)، اسم ودور المستخدم المصادق، عنوان الـ IP للعميل، وزمن استجابة المعالجة بالأجزاء من الثانية لضمان القدرة على المراجعة الجنائية للحدث.

## 3. التدابير الوقائية ضد هجمات إساءة استخدام الذكاء الاصطناعي

### أ. حماية حقن البرومبت والذاكرة (`is_prompt_injection`)
* **المسار**: `ai_project/utils/security.py`
* تفحص المدخلات المرسلة لمحركات الاستدلال وحفظ الذاكرة ضد هجمات حقن الأوامر (Prompt Injection) وتسميم الذاكرة (RAG Poisoning).
* **الأنماط المفحوصة (Regex)**:
  * كشف محاولات إلغاء أو تجاوز التعليمات التأسيسية (مثل `ignore previous instructions` أو `bypass restrictions`).
  * كشف محاولات استخراج تعليمات النظام المكتوبة مسبقاً (مثل `reveal your system prompt`).
  * كشف محاولات كسر الحماية الشائعة (مثل `dan mode` أو `jailbreak`).

### ب. منع محاولات استكشاف الشبكات الداخلية (`validate_url_ssrf`)
* تقييد مسارات استدعاء الروابط الخارجية لمنع المهاجمين من استغلال الخادم لمهاجمة الأجهزة الداخلية (Server-Side Request Forgery).
* تمنع البرمجية طلب أي رابط يشير لشبكات محلية أو عناوين استرجاع مثل `127.0.0.1` أو شبكات الفئة A/B/C الخاصة، وتحظر البروتوكولات غير الآمنة مثل `file://` و `ftp://`.

### ج. حماية مسار الملفات وحظر الاختراق الهيكلي (`resolve_safe_path`)
* **المسار**: `ai_project/utils/path_safety.py`
* تقوم بالتحقق من مسارات الملفات المطلوبة للرفع أو القراءة والتأكد من عدم استخدام رموز تراجع مثل `../` للهروب خارج مجلد العمل المخصص (Directory Traversal Attack).

## 4. بيئة التنفيذ المعزولة (Secure Execution Sandbox)

* **المسار**: `ai_project/agents/sandbox.py`
* **المعزل الأساسي (Docker Sandbox)**:
  * يتم عزل الأكواد البرمجية البرمجية المطلوب تنفيذها داخل حاويات Docker مخصصة.
  * **قيود العزل**:
    1. **شبكة معطلة كلياً (`network_disabled=True`)**: لمنع الكود من الاتصال بخوادم خارجية أو تسريب البيانات.
    2. **ملف نظام للقراءة فقط (`read_only=True`)**: لمنع تعديل ملفات الخادم المضيف.
    3. **تحديد الموارد**: تقييد حجم الذاكرة العشوائية المستهلكة والمعالج تفادياً لهجمات الحرمان من الخدمة (DoS).
    4. **التنظيف التلقائي الفوري**: حذف الحاوية والملفات المؤقتة تلقائياً فور انتهاء المعالجة.
* **المعزل الاحتياطي (Subprocess Fallback)**:
  * في حال غياب محرك Docker في بيئة التشغيل، يتم تشغيل الكود عبر عملية فرعية (Subprocess) معزولة جزئياً مع تقييد مهلة التنفيذ وحظر استخدام مكتبات حساسة مثل `os` و `sys` و `subprocess` في الكود المرسل.
