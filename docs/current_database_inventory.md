# Phoenix AI - جرد هياكل وقواعد البيانات الحالية (Current Database Inventory)

يوثق هذا الملف هياكل وقواعد البيانات المعتمدة حالياً في منصة **Phoenix AI**، مع شرح النماذج التخطيطية (Schemas) والمفاتيح ونوعية البيانات ونماذج التضمين.

---

## 1. بنية بنك الذاكرة المتجهية والمعرفية (`memory_db.json`)

يتم حفظ الذاكرة الطويلة الأجل ومستندات RAG دلالياً في الملف التالي:
* **المسار**: `ai_project/memory/memory_db.json`
* **نوع التخزين**: مستند JSON منظم ومكتوب بطريقة ذرية (Atomic Write) باستخدام ملف مؤقت `.tmp` لضمان عدم تعرض البيانات للتلف عند الانقطاع الكهربائي أو توقف الخادم المفاجئ.

### أ. الهيكل التخطيطي الكلي (JSON Schema)
يحتوي الملف على كائنين رئيسيين:
1. `memories`: مصفوفة من العناصر النصية مرفقة ببياناتها الوصفية والتضمين المتجهي الخاص بها.
2. `kg_graph`: رسم بياني يمثل الكيانات المعرفية وعلاقاتها المترابطة (Knowledge Graph).

```json
{
  "memories": [
    {
      "text": "النص المدخل أو المستخلص دلالياً",
      "metadata": {
        "type": "interaction | manual | upload",
        "access_count": 12,
        "last_accessed": 1782169893.35,
        "importance": 2.1,
        "compressed": false
      },
      "embedding": [
        0.05440229, -0.00410351, 0.08432687
      ]
    }
  ],
  "kg_graph": {
    "phoenix ai": [
      ["is a", "generative ai platform"],
      ["developed by", "deepmind team"]
    ]
  }
}
```

### ب. تفاصيل المتجهات المدمجة (Vector Configuration)
* **أبعاد المتجه (Embedding Dimensions)**: `dim = 512` (أو ما يماثل أبعاد طبقة `dim` في أوزان نموذج `Phoenix-54M`).
* **مصدر التضمين**: يتم استخدام طبقة التضمين النصية للنموذج ذاته (`model.tok_embeddings`) مع احتساب المتوسط عبرSequence length ثم إجراء تسوية رياضية L2 (L2 Normalization) ليكون مربع طول المتجه مساوياً لـ `1`.
* **مقياس التطابق (Similarity Metric)**: المسافة الجيبية (Cosine Similarity) التي تُحسب عبر الضرب الاتجاهي (Dot Product) للمتجهات المسواة.

### ج. هيكلية الرسم البياني المعرفي (Graph RAG Structure)
* يتم استخلاص الكيانات تلقائياً في بايثون باستخدام تعابير نمطية تفاعلية (Regex Patterns) تكشف الجمل الخبرية (مثل `X is a Y` أو `X developed Y`).
* يخزن الحقل `kg_graph` الكيان كمفتاح (Key) ومصفوفة العلاقات كقيم ثنائية `[relation, target_entity]`.

## 2. بنية قاعدة بيانات مستكشف الذكاء الاصطناعي (`ai_data.json`)

تخزن المنصة بيانات وتصنيفات نماذج الذكاء الاصطناعي في الملف التالي ليكون مرجعاً للمطورين:
* **المسار**: `ai_project/api/ai_data.json`
* **نوع التخزين**: ملف JSON مسطح.

### الهيكل التخطيطي للبيانات (Schema)
يحتوي الملف على مصفوفة تصنيفات كبرى (`categories`) وبداخل كل تصنيف مصفوفة نماذج فرعية (`models`):

| الحقل | النوع | الوصف | مثال |
|:---|:---:|:---|:---|
| `categories` | Array | قائمة تصنيفات الذكاء الاصطناعي | - |
| `categories.id` | String | المعرف الفريد للتصنيف | `gen_ai` |
| `categories.name` | String | الاسم المعرب للتصنيف | `الذكاء الاصطناعي التوليدي` |
| `categories.description` | String | شرح مبسط لطبيعة التصنيف | `نماذج قادرة على توليد...` |
| `categories.models` | Array | قائمة الموديلات المسجلة بالتصنيف | - |
| `categories.models.name` | String | اسم الموديل التجاري | `GPT-4o` |
| `categories.models.developer` | String | الشركة المطورة للموديل | `OpenAI` |
| `categories.models.type` | String | النوع التقني لشبكة الموديل | `Multimodal LLM` |
| `categories.models.parameters`| String | حجم البارامترات والأوزان | `1.8T` |
| `categories.models.use_case` | String | سيناريو الاستخدام الأمثل | `توليد النصوص والأكواد...` |

## 3. مخزن المستخدمين المؤقت في الذاكرة (`_users_store`)

تمتلك المنصة نظام مصادقة وصلاحيات يعتمد على مستودع مستخدمين مؤقت في الذاكرة (In-Memory Store) داخل الملف التالي:
* **المسار**: `ai_project/api/auth.py`
* **المتغير**: `_users_store` (قاموس Dict بايثون).

### هيكل سجلات المستخدم (User Record Schema)
```python
{
    "user_id": {
        "id": "معرف UUID فريد عشوائي (String)",
        "username": "اسم المستخدم الفريد (String)",
        "password_hash": "الرمز المشفر للسر (String)",
        "role": "الأدوار: admin | developer | operator | user",
        "created_at": "تاريخ الإنشاء بصيغة Unix Timestamp (Int)"
    }
}
```

### خوارزمية التشفير وحماية كلمات السر
* لا يتم استخدام مكتبة `bcrypt` المباشرة لتجنب مشاكل التجميع والـ Build على أنظمة التشغيل المختلفة.
* تم استبدالها بخوارزمية التشفير المتطورة المدمجة في بايثون **PBKDF2-SHA256** مع استخدام ملح عشوائي فريد لكل كلمة سر (Unique Salt) وعدد تكرارات تشفيرية يبلغ `100,000` دورة لمنع هجمات المعاجم أو جداول قوس قزح (Rainbow Tables).

## 4. الفجوات وقصور الهيكلية الحالية (Technical Database Gaps)

1. **الافتقار لقاعدة بيانات علائقية موحدة**: حفظ بيانات المستخدمين في ذاكرة خادم FastAPI النشطة يعني مسح الحسابات بالكامل عند إعادة تشغيل التطبيق أو الحاوية.
2. **غياب موازنة الأحمال وقابلية التوسع الأفقي**: لا يمكن تشغيل أكثر من خادم ويب واحد خلف Nginx لأن كل خادم سيحتفظ بذاكرة مستخدمين وملف RAG منفصل، مما يسبب تشتت البيانات وغياب الاتساق الثنائي (Data Inconsistency).
3. **التضمين المتجهي البسيط**: الاعتماد على نموذج الاستدلال ذي الحجم الصغير Phoenix-54M لتوليد المتجهات يقلل من الدقة المعرفية مقارنة بالمحركات المتخصصة.
4. **تخزين نصوص RAG بصيغة غير مشفرة**: تُحفظ الملفات والذاكرة في ملف JSON على شكل نصوص صريحة (Plain Text) مما يشكل خطراً أمنياً على سرية البيانات المخزنة محلياً.
5. **توصية الترقية للإنتاج الكلي**: يجب ترحيل هياكل مستكشف الذكاء والمستخدمين لقاعدة بيانات **PostgreSQL** وترحيل مصفوفات المتجهات لمحرك **Qdrant** مع تفعيل تشفير البيانات المخزنة (Encryption at Rest).
