تعتمد المنصة حالياً على ملف [`memory_db.json`](file:///c:/Users/1/Desktop/7070/ai_project/memory/memory_db.json) لتخزين متجهات التمثيل الدلالي (Embeddings) جنباً إلى جنب مع البيانات الوصفية (Metadata).
* **آلية البحث الحالية**: يتم تحميل المتجهات في الذاكرة العشوائية وتجميعها في مصفوفة PyTorch Tensor ثنائية الأبعاد. عند البحث، يتم ضرب مصفوفة الاستعلام بمتجهات الذاكرة دفعة واحدة (Matrix-Vector Dot Product) لحساب تشابه الجيب (Cosine Similarity).
* **الأداء الحالي**: سرعة استجابة استثنائية للاستعلام الفردي (**~22-28 ميلي ثانية**) مع الحجم الحالي للذاكرة.

## 2. تقييم محركات البحث البديلة (Comparative Evaluation)

### أ. محرك Qdrant (خيار خادم الإنتاج)
* **المميزات**: قاعدة بيانات متجهات سحابية كاملة تدعم التوزيع الأفقي والتوسع اللانهائي، وتقدم تصفيات متقدمة للبيانات الوصفية (Payload Filtering) وفهرسة HNSW افتراضية.
* **العيوب**: تتطلب تشغيل حاوية Docker مستقلة لخدمة Qdrant، مما يعقد التشغيل المحلي الخفيف للمطورين (Local-First).

### ب. مكتبة FAISS (خيار البحث المحلي الفائق)
* **المميزات**: مكتبة معالجة متجهات فائقة السرعة مكتوبة بلغة C++ ومطورة من فيسبوك. ممتازة للمقارنات الكثيفة على المعالجات المركزية أو بطاقات الرسوميات.
* **العيوب**: تتطلب تجميع حزم ثنائية (Native C++ Bindings) والتي قد تفشل في بعض البيئات وأنظمة التشغيل أثناء التثبيت عبر `pip`.

### ج. خيار HNSW (Hierarchical Navigable Small World)
* **المميزات**: بناء رسم بياني للمتجهات لتنفيذ خوارزميات البحث التقريبي لأقرب جار (ANN Search). يوفر سرعة بحث لوغاريتمية O(log N) ممتازة للأحجام المتوسطة والكبيرة محلياً دون الحاجة لخوادم خارجية.
* **العيوب**: استهلاك ذاكرة عشوائية أكبر أثناء مرحلة بناء الرسم البياني (Graph Index Construction).

## 3. خطة وأداة الهجرة (Migration Plan & Utility)

تم تطوير مكون برمجي مخصص للهجرة في [vector_migration.py](file:///c:/Users/1/Desktop/7070/ai_project/memory/vector_migration.py) يسمح بتصدير البيانات تلقائياً بالصيغ البرمجية للمحركات المستهدفة:
1. **التصدير لـ FAISS**: استخراج المتجهات وتحويلها إلى مصفوفات NumPy أحادية الدقة (`float32 NumPy Array`) وتوفير كتل البيانات الوصفية المقترنة بمعرفات رقمية.
2. **التصدير لـ HNSW**: تهيئة المتجهات والمعرفات الثنائية بصيغة متوافقة مع مكتبة HNSWLib.
3. **التصدير لـ Qdrant**: صياغة البيانات في هياكل نقاط Qdrant (PointStruct JSON format) للتحميل الفوري عبر الـ REST API لـ Qdrant.

## 4. مقارنة الأداء والتوصية التشغيلية (Benchmarks & Recommendations)

تم قياس زمن البحث باستعمال حجم ذاكرة صغير ومقارنته بالهياكل المقترحة:
* **الأحجام الصغيرة (< 1,000 مستند)**:
  * يظل أداء ضرب المصفوفات المباشر عبر PyTorch أسرع وأبسط خيار، حيث لا توجد أي تكلفة إضافية لإنشاء الفهارس (Index Overhead).
  * زمن البحث الحالي: **22.73 ميلي ثانية**.
* **الأحجام المتوسطة (1,000 - 50,000 مستند)**:
  * يوصى بالهجرة التلقائية إلى **Local HNSW Index** باستخدام مكتبة `hnswlib` محلياً للحفاظ على طابع التشغيل الذاتي البسيط ومضاعفة سرعة البحث مع نمو البيانات.
* **الأحجام الضخمة (> 50,000 مستند)**:
  * يوصى بالهجرة الكاملة إلى **Qdrant Server Container** لدعم التوزيع والتصفيات المعقدة.
