# Phoenix AI - جرد منظومة العمليات والنشر الحالية (Current DevOps Inventory)

يوضح هذا المستند جردًا تفصيليًا للملفات وإعدادات البنية التحتية البرمجية، وعمليات التكامل والتحقق المستمر (CI/CD)، ونصوص الأتمتة المعتمدة لتشغيل وصيانة منصة **Phoenix AI**.

---

## 1. إعدادات بيئة النشر والحاويات (Docker & Compose Config)

تعتمد المنصة على تقنية الحاويات (Containerization) لتبسيط التشغيل وضمان اتساق البيئات التشغيلية:

### أ. حاوية الواجهة الخلفية (`Dockerfile.backend`)
* **الصورة الأساسية**: `python:3.10-slim` (صورة خفيفة ومستقرة لبيئات بايثون).
* **خطوات البناء**:
  1. تحديث النظام وتثبيت حزمة `build-essential` لتجميع حزم بايثون التي تتطلب الترجمة البرمجية بلغة C/C++.
  2. نسخ وتثبيت ملف الاعتمادات `requirements.txt`.
  3. نسخ ملفات المشروع وتحديد المتغير البيئي `PYTHONPATH=/app` للتأكد من صحة مسارات استيراد المكتبات الداخلية.
  4. تحديد أمر التشغيل الافتراضي لتشغيل خادم Uvicorn على المنفذ `8000`.

### ب. حاوية الواجهة الأمامية (`Dockerfile.frontend`)
* **البناء متعدد المراحل (Multi-stage Build)**:
  * **المرحلة الأولى (Builder)**: تستخدم صورة `node:18-alpine` لتثبيت مكتبات npm البرمجية وبناء وتجميع ملفات الإنتاج لـ React (`npm run build`).
  * **المرحلة الثانية (Nginx)**: تستخدم صورة `nginx:alpine` الخفيفة جداً، حيث يتم نسخ ملف الإعدادات `nginx.conf` ونسخ مخرجات التجميع للمجلد `/usr/share/nginx/html` وتصديرها على المنفذ `80`.

### ج. إعداد التنسيق والربط بين الخدمات (`docker-compose.yml`)
* يربط الخدمتين (Frontend & Backend) في شبكة افتراضية موحدة:
  * خادم الويب **Backend**: يفتح المنفذ `8000:8000` ويقوم بتركيب مجلدات ربط حجمية (Volume Mounts) لمجلد الذاكرة `memory/` ونقاط حفظ الموديلات لضمان استدامة البيانات (Data Persistence).
  * خادم العرض **Frontend**: يفتح المنفذ `80:80` ويعتمد تشغيله على جاهزية الخادم الخلفي (`depends_on: backend`).

### د. خادم الويب العكسي (`nginx.conf`)
* يستمع للمنفذ `80` ويقوم بالتوجيه الذكي:
  * تمرير طلبات الصفحة الرئيسية والمسارات الفرعية لملف `index.html` لدعم التنقل الداخلي في React Router.
  * توجيه طلبات الواجهة الخلفية التي تبدأ بـ `/api` تلقائياً إلى خادم الباكيند `http://backend:8000`.

## 2. خط أنابيب التكامل والتحقق المستمر (GitHub Actions CI)

* **ملف الإعداد**: `.github/workflows/ci.yml`
* **محفز التشغيل**: أي عملية دفع للكود (Push) أو طلب دمج (Pull Request) إلى الفروع الرئيسية (`main`, `master`).
* **مراحل ومهام خط الأنابيب**:
  1. **مرحلة التدقيق اللغوي والأكواد (Lint)**:
     * تهيئة بايثون 3.12 وتثبيت أداة `flake8` للتحقق من خلو الأكواد من الأخطاء النحوية أو المتغيرات غير المعرفة لتجنب تعثر التشغيل.
  2. **مرحلة الاختبارات التلقائية (Test)**:
     * تثبيت متطلبات النظام والمكتبات البرمجية الحساسة بما فيها مكتبة PyTorch (نسخة المعالج CPU).
     * تشغيل **3 حزم اختبارات مستقلة**:
       * حزمة اختبارات النظام الأساسية: `pytest tests/`
       * حزمة اختبارات مدير المهام: `pytest task_manager/tests/`
       * حزمة اختبارات الخلفية للمهام: `pytest phoenix_tasks/backend/tests/`
  3. **مرحلة التحقق من البناء الفعلي (Build)**:
     * تهيئة بيئة Node.js 18 وبناء الواجهة الأمامية React للتأكد من سلامة كود الجافاسكريبت.
     * إجراء عملية بناء تجريبية (Dry Run) لصور Docker للباكيند والفرونتد للتأكد من خلو ملفات الـ Dockerfiles من أي أخطاء تمنع التعبئة.

## 3. نصوص الأتمتة والعمليات الاحتياطية (Scripts Directory)

لتسهيل أعمال الصيانة والتعافي من الكوارث، تحتوي المنصة على نصوص برمجية مخصصة:

### أ. نص النسخ الاحتياطي والاستعادة لنظام Linux/macOS (`backup_restore.sh`)
* يتولى إيقاف قواعد البيانات مؤقتاً، نسخ ملف `memory_db.json` وضغطه وإضافة البصمة الزمنية، فحص سلامة الملف الاحتياطي الناتج وحفظه في مجلد النسخ الاحتياطي الدائم، مع توفير خيار استعادة سريع من ملف محدد.

### ب. نص النسخ الاحتياطي والاستعادة لنظام Windows PowerShell (`backup_restore.ps1`)
* يؤدي نفس المهام الاحتياطية والاستعادية بالاعتماد على بيئة PowerShell لنظام تشغيل ويندوز، مع فحص وجود الملفات وإرسال رسائل النجاح أو الفشل الموثقة.

### ج. نصوص بدء التشغيل السريع (`run_phoenix.bat`)
* ملف دفعي لويندوز يقوم بتفعيل البيئة الافتراضية بايثون وتثبيت أي اعتمادات ناقصة وتشغيل خادم التطوير للواجهة الخلفية والأمامية بالتزامن.
